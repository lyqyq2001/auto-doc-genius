# AutoDoc Genius 图片替换功能技术方案

> 状态：待评审
> 日期：2026-10-21
> 涉及版本：auto-doc-genius 0.0.0（docxtemplater ^3.67.6 / Electron ^39.2.7）

---

## 1. 背景与目标

当前项目支持两类占位符：

| 类型     | Excel 表头        | Word 模板写法                | 处理位置                                                 |
| -------- | ----------------- | ---------------------------- | -------------------------------------------------------- |
| 文本替换 | `XXX01`、`XXX02`… | 直接写 `XXX01`               | `src/utils/docxGenerator.js`                             |
| 复选框   | `check01`…        | `{{check01□ 选项1 □ 选项2}}` | `src/utils/documentUtils.js` 的 `processCheckboxOptions` |

**目标**：新增"图片占位符"能力——Word 模板中指定位置放置图片占位符，生成文档时按 Excel 数据行提供的图片，将占位符替换为真实图片，且 Word 导出与 PDF 导出两条链路均可用。

---

## 2. 现状架构分析

### 2.1 生成链路

```
App.vue startGenerate()
  ├─ parseExcel()                    // documentUtils.js：解析表头(第2行)+数据行(第3行起)
  ├─ readWordTemplate()              // 模板读为 ArrayBuffer
  ├─ 循环每行:
  │    generateDocx(template, rowData, i)   // docxGenerator.js
  │      ├─ PizZip 解压模板
  │      ├─ 遍历所有 .xml：processCheckboxOptions() 处理复选框
  │      ├─ 将裸占位符 XXX01 包裹为 docxtemplater 标签 {XXX01}
  │      ├─ docxtemplater.render(rowData)
  │      └─ 输出 docx ArrayBuffer
  ├─ (PDF 模式) IPC batch-convert-pdf → Word/WPS COM 转换
  └─ JSZip 打包 → file-saver 下载
```

### 2.2 对图片替换有利的现状

1. **每行数据都从模板重新 zip 一份**（`generateDocx` 内部 `new PizZip(wordTemplate)`），各行互不影响——天然支持"每行不同图片"。
2. **已有直接改写 OOXML 字符串的先例**（`processCheckboxOptions` 就是在 XML 文本层面做替换），图片注入可沿用同一模式。
3. **PDF 链路无需改造**：PDF 由 Word/WPS COM 从生成的 docx 转换而来，Word 原生支持文档内图片。

### 2.3 约束

- 渲染进程 `contextIsolation: true`、`nodeIntegration: false`（`electron/main.js`），**前端无法直接读本地文件**，读取图片必须走 IPC。
- `xlsx@0.18.5` 社区版**不支持读取 Excel 单元格内嵌图片**（属 Pro 付费能力），因此图片来源不能设计为"Excel 里贴图"。
- `electron-builder` 的 `build.files` 是白名单制（见 `package.json`），**新增的 Node 依赖必须显式加入打包列表**，否则安装包内主进程 `require` 会失败。

## 3. 需求与约定设计

### 3.1 图片来源

Excel 单元格中填写**图片文件路径**：

- 绝对路径：`D:\photos\user1.jpg`
- 相对路径：`photos/user1.jpg`（相对于 Excel 文件所在目录解析，便于"Excel + 图片文件夹"整体拷贝分发）

### 3.2 占位符约定（与现有风格保持一致）

| 项         | 约定                                                                          |
| ---------- | ----------------------------------------------------------------------------- |
| Excel 表头 | 以 `img` 开头（不区分大小写）的列识别为图片列，如 `img01`、`IMG_photo`        |
| Word 模板  | 在需要图片的位置直接写 `img01`（与 `XXX01` 写法一致），**建议单独占一个段落** |
| 支持格式   | `png` / `jpg` / `jpeg` / `gif` / `bmp`                                        |
| 尺寸策略   | 按图片原始宽高比嵌入；宽度超过 **15cm** 时等比缩放至 15cm 以内                |
| 缺图处理   | 文件不存在或解码失败时：移除占位符、留空，计入警告，生成结束后弹通知汇总      |

示例：

| name | img01               |
| ---- | ------------------- |
| 张三 | photos/zhangsan.jpg |
| 李四 | D:\pics\lisi.png    |

模板中写 `姓名：name`、`照片：img01`（`img01` 单独一段）。

## 4. 方案选型对比

| 方案                                     | 说明                                                                                                           | 优点                                                                            | 缺点                                                                         |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| A. 社区插件 `docxtemplater-image-module` | npm 免费（MIT），`{%img01}` 标签                                                                               | 代码量少                                                                        | 多年未维护，与 docxtemplater 3.67 兼容性存在风险；尺寸控制弱；引入不可控依赖 |
| B. 官方 `@docxtemplater/image-module`    | docxtemplater 官方维护                                                                                         | 稳定、支持好                                                                    | **商业授权（付费）**，与本项目定位不符                                       |
| C. **自研 XML 注入（推荐）**             | 沿用 `processCheckboxOptions` 的思路，在 XML 层面把占位符所在 run 替换为 `<w:drawing>`，并把图片写入 docx 包内 | 零新增运行时依赖（或仅 1 个 10KB 工具库）、完全可控、与现有架构一致、无授权问题 | 需编写约 200 行 OOXML 处理代码                                               |

**结论：选 C。** 项目已经在做 XML 文本级改写，能力匹配；图片注入逻辑在每行数据的独立 zip 副本内闭环，复杂度可控。

## 5. 总体设计（方案 C）

### 5.1 数据流

```
parseExcel 得到行数据
  → 识别 img 开头的列，收集全表图片路径（去重）
  → 相对路径用 Excel 所在目录补全为绝对路径
  → IPC 'read-image-files'：主进程读文件 + 解析宽高
  ← 返回 { path: { ok, base64, width, height, ext } }
  → generateDocx(template, rowData, i, imageAssets)
       ├─ 将 document.xml 中含 img01 的 <w:r> 替换为 <w:drawing>
       ├─ 图片字节写入 word/media/xxx.ext
       ├─ word/_rels/document.xml.rels 注册 rId
       └─ [Content_Types].xml 按需补 <Default Extension=...>
  → docxtemplater 正常渲染其余文本/复选框占位符
```

### 5.2 IPC 设计

**`electron/preload.js` 新增：**

```js
const { contextBridge, ipcRenderer, webUtils } = require('electron');

contextBridge.exposeInMainWorld('electronAPI', {
  // ...现有接口保留
  // 获取文件真实路径（Electron 新版 File.path 已废弃，统一用 webUtils）
  getFilePath: file => webUtils.getPathForFile(file),
  // 批量读取图片
  readImageFiles: paths => ipcRenderer.invoke('read-image-files', paths),
});
```

**`electron/main.js` 新增：**

```js
const sizeOf = require('image-size');

const IMAGE_EXTS = new Set(['.png', '.jpg', '.jpeg', '.gif', '.bmp']);

ipcMain.handle('read-image-files', async (_event, paths) => {
  const result = {};
  for (const p of paths) {
    try {
      const normalized = path.normalize(p);
      const ext = path.extname(normalized).toLowerCase();
      if (!IMAGE_EXTS.has(ext)) throw new Error(`不支持的图片格式: ${ext}`);
      const buffer = fs.readFileSync(normalized);
      const dim = sizeOf(buffer); // { width, height, type }
      result[p] = {
        ok: true,
        base64: buffer.toString('base64'),
        width: dim.width,
        height: dim.height,
        ext: ext.replace('.', ''),
      };
    } catch (e) {
      result[p] = { ok: false, error: e.message };
    }
  }
  return result;
});
```

要点：

- **新增依赖 `image-size`**（约 10KB，纯 JS，仅主进程使用）。必须在 `package.json` 的 `build.files` 中加入 `"node_modules/image-size/**/*"`，否则打包后主进程 require 失败。
- 若不想引入依赖，也可自写 PNG/JPEG 文件头解析（约 50 行）获取宽高，作为备选。
- 安全：扩展名白名单 + `path.normalize`；相对路径只允许基于 Excel 目录解析，防止任意文件读取。
- 渲染进程传参前**按路径去重**（多行复用同一图片只读一次）。

### 5.3 路径解析

- 通过 `electronAPI.getFilePath(excelFile)` 获取 Excel 真实路径（`webUtils.getPathForFile`），取其目录作为相对路径基准。
- 纯浏览器环境（无 `electronAPI`）下无法解析相对路径：提示用户必须填绝对路径。

### 5.4 `docxGenerator.js` 改造

`generateDocx(wordTemplate, rowData, index, imageAssets)` 新增第 4 个参数，处理顺序：

1. **图片注入（新增，放在最前）**：对每个 `img` 开头的 key，在 `word/document.xml` 中定位包含占位符文本的 `<w:r>...</w:r>`，整体替换为绘图 XML（见 5.5）；同时完成 media 写入、rels 注册、Content Types 检查。
2. `processCheckboxOptions`（不变）。
3. 占位符包裹循环中**跳过 `img` 开头的 key**（避免被包成 `{img01}` 文本标签）。
4. `docxtemplater.render(rowData)`（img 列留在 rowData 中无副作用，已无对应标签）。

### 5.5 绘图 XML 模板

占位符 run 替换为（`{cx}`/`{cy}` 为 EMU 尺寸，`{rId}` 为关系 ID，`{docPrId}` 文档内唯一递增）：

```xml
<w:r>
  <w:drawing>
    <wp:inline distT="0" distB="0" distL="0" distR="0">
      <wp:extent cx="{cx}" cy="{cy}"/>
      <wp:effectExtent l="0" t="0" r="0" b="0"/>
      <wp:docPr id="{docPrId}" name="Picture {docPrId}"/>
      <wp:cNvGraphicFramePr>
        <a:graphicFrameLocks xmlns:a="http://schemas.openxmlformats.org/drawingml/2006/main" noChangeAspect="1"/>
      </wp:cNvGraphicFramePr>
      <a:graphic xmlns:a="http://schemas.openxmlformats.org/drawingml/2006/main">
        <a:graphicData uri="http://schemas.openxmlformats.org/drawingml/2006/picture">
          <pic:pic xmlns:pic="http://schemas.openxmlformats.org/drawingml/2006/picture">
            <pic:nvPicPr>
              <pic:cNvPr id="{docPrId}" name="{fileName}"/>
              <pic:cNvPicPr/>
            </pic:nvPicPr>
            <pic:blipFill>
              <a:blip r:embed="{rId}"/>
              <a:stretch><a:fillRect/></a:stretch>
            </pic:blipFill>
            <pic:spPr>
              <a:xfrm><a:off x="0" y="0"/><a:ext cx="{cx}" cy="{cy}"/></a:xfrm>
              <a:prstGeom prst="rect"><a:avLst/></a:prstGeom>
            </pic:spPr>
          </pic:pic>
        </a:graphicData>
      </a:graphic>
    </wp:inline>
  </w:drawing>
</w:r>
```

**单位换算**：1 像素(96dpi) = 9525 EMU；最大宽度 15cm = 5,400,000 EMU。

```js
const PX_TO_EMU = 9525;
const MAX_WIDTH_EMU = 5400000; // 15cm
let cx = width * PX_TO_EMU;
let cy = height * PX_TO_EMU;
if (cx > MAX_WIDTH_EMU) {
  cy = Math.round(cy * (MAX_WIDTH_EMU / cx));
  cx = MAX_WIDTH_EMU;
}
```

**配套写入：**

- 图片文件：`templateZip.file('word/media/img_${index}_${seq}.${ext}', base64, { base64: true })`
- `word/_rels/document.xml.rels`：在 `</Relationships>` 前插入

```xml
<Relationship Id="{rId}" Type="http://schemas.openxmlformats.org/officeDocument/2006/relationships/image" Target="media/{fileName}"/>
```

（rId 取现有最大值递增，避免与模板已有关系冲突）

- `[Content_Types].xml`：检查并补齐对应扩展名（docx 模板通常不含图片类型声明）：

```xml
<Default Extension="png" ContentType="image/png"/>
<Default Extension="jpg" ContentType="image/jpeg"/>
<Default Extension="jpeg" ContentType="image/jpeg"/>
<Default Extension="gif" ContentType="image/gif"/>
<Default Extension="bmp" ContentType="image/bmp"/>
```

### 5.6 `App.vue` 流程改造

在 `startGenerate` 中、`parseExcel` 之后、生成循环之前插入：

1. 扫描表头，找出 `img` 开头列；若无则完全走旧逻辑（零影响）。
2. 收集所有单元格路径 → 相对路径补全 → 去重。
3. 调 `electronAPI.readImageFiles(paths)` 得到 `imageAssets`。
4. 失败项汇总警告（`ElNotification.warning` 提示缺失文件清单，继续生成）。
5. `generateDocx(wordTemplate, rowData, i, imageAssets)`。

### 5.7 i18n 与模板

- `src/locales/zh.json` / `en.json` 新增：图片列说明、图片读取失败、缺失图片数量提示等文案。
- `public/Word Template.docx`、`public/Word Template (English).docx` 增加 `img01` 示例段落。
- `public/Excel Template.xls`（及英文版）增加 `img01` 示例列。

## 7. 边界情况与风险

| 风险                               | 应对                                                                                                  |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 占位符在模板中被 Word 拆成多个 run | 与现有 `XXX01` 机制同等限制：模板编写时占位符需连续（模板说明中注明）；后续可增强"合并相邻 run"预处理 |
| 大图 × 多行导致内存压力            | 路径去重 + 缓存；必要时限制单图大小（如 10MB）并提示                                                  |
| base64 IPC 传输开销（约 +33%）     | 首版可接受；若成瓶颈改为结构化克隆传 ArrayBuffer                                                      |
| GIF 动图                           | Word 仅显示第一帧，属正常行为，文档中说明                                                             |
| `image-size` 解析失败              | 回退默认尺寸 200×200 并警告                                                                           |
| 新增 Node 依赖未进打包白名单       | 改动清单已列明，构建后需实测安装包                                                                    |
| 相对路径越权（`..\`）              | `path.normalize` 后校验仍位于 Excel 目录之下                                                          |

## 8. 测试要点

1. 格式覆盖：png / jpg / jpeg / gif / bmp。
2. 路径覆盖：绝对路径、相对路径、含空格与中文的路径、不存在的路径、损坏文件、不支持的扩展名。
3. 场景覆盖：单图列、多图列、多行复用同一图片、图片列与普通列/复选框列混合。
4. 输出验证：生成的 docx 用 Word 与 WPS 分别打开，图片显示、尺寸比例正确；PDF 导出链路图片正常。
5. 回归：不含图片列时，现有文本替换、复选框、批量生成、打包下载行为完全不变。
6. 安装包验证：`npm run build` 后在干净环境运行安装包，确认 `image-size` 可被主进程加载。
